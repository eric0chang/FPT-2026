summary: In a line-buffer / sliding-window convolution, fully unroll every loop that shifts the window or the line buffer (UNROLL on each loop, not only the outermost one) and completely partition those arrays, so the shift takes one cycle.

Symptom: in the csynth Performance table, small loops (trip count 3, 4, 20, ...) appear under the pixel loop; each runs as its own little pipeline, one after another.
Check: no loop rows between the pixel loop and the MAC loop.
Observed in a past LeNet run: UNROLL only on the channel loop left the ky/kx shift loops rolled, costing 27 cycles per pixel in conv1 and 81 in conv2 (3 input channels), for a shift that needs 1 cycle.
