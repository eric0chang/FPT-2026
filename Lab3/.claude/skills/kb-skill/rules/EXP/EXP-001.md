A float sum carried from one iteration to the next puts float adders on the loop-carried path; the tool can chain them in one cycle.
Observed in two past LeNet runs on Vitis HLS 2025.2: `sum += e[o]` in the softmax was scheduled as two chained 32-bit `fadd` (6.437 ns each) in one cycle: estimated clock 13.301 ns against a 10 ns target (7.3 ns budget after uncertainty), HLS 200-871 / 200-1016 in module `dense_out_softmax`. The same code met timing in 2023.2 and 2024.2, so a passing run on an older tool does not prove it.
A fixed-point sum uses a plain 32-bit adder (about 1-2 ns), not a float core, so it stays far inside the budget; a past design summed the exponentials in `ap_ufixed<32,4>` (float `hls::expf`, one float divide per class) and kept full accuracy.
