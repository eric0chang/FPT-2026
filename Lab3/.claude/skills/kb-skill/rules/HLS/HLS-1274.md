Width and signedness come from the operands; the destination only extends or truncates afterwards.
- `a+b`, `a-b`: max(Wa,Wb)+1, or +2 when the wider operand is unsigned and the narrower signed; `+` is signed if either operand is, `-` is always signed.
- `a*b`: Wa+Wb, signed if either operand is.
- `a/b`: Wa for an unsigned divisor, Wa+1 for a signed one; signed if either operand is.
- `a%b`: min(Wa,Wb) when both share signedness, Wb+1 for a signed a with an unsigned b; takes a's signedness.
- `a&b`, `a|b`, `a^b`: max(Wa,Wb), unsigned only when both operands are; `~a` keeps a's width and signedness.
- `-a`: Wa for signed a, Wa+1 for unsigned a; always signed.
Native operands count as char 8, short 16, int 32, long 32, long long 64 bits. Compound forms (`+=`, `<<=`, ...) evaluate the RHS by these rules, apply the base operator, then fit the result into the LHS width.
Manual inconsistency: its example labels a 42-bit unsigned + 23-bit signed sum as 43 bits, while the rule gives 44; size for the larger.

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > Binary Arithmetic Operators, pp. 680-686.
