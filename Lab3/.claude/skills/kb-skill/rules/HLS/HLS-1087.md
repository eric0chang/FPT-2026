A bare `T *p` does not tell Vitis HLS how many values pass through the port, so unless the code bounds it (for example with an array size) co-simulation provides one input and accepts one output; a port needing more waits for data or space that never comes. Validate the C model first to confirm the intended access pattern.
Without `volatile`, HLS (like any C compiler, in line with the C standard) optimizes the intermediate accesses away, so the port sees one read and one write per call; a missing depth on a volatile interface pointer is a listed cause of co-simulation failure.
```cpp
#pragma HLS INTERFACE mode=ap_fifo port=in depth=4
```
Also covered in UG1399 Ch.12 Building and Running an HLS Component > Troubleshooting C/RTL Co-Simulation, p. 390.

Source: UG1399 v2023.2, Ch.6 Data Types > Pointers on the Interface > Multi-Access Pointers and RTL Simulation, pp. 138-141.
