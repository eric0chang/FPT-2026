- A Vitis kernel (.xo) is a Vivado IP with extra interface requirements and limitations; Vivado IP has few restrictions. The same source can therefore get different ports in the two flows, and `#pragma HLS INTERFACE` (or the directive) overrides a default that does not suit the surrounding system.
- Vitis kernel flow: port-level protocols are fixed in most cases, and the manual advises keeping the defaults unless necessary. The tool infers s_axilite itself for scalars, m_axi base addresses and the return value. Typical RTL: `ap_clk`, `ap_rst_n`, `interrupt`, one `s_axi_control`, one `m_axi_gmem` holding all pointer arguments.
- Pointer-to-scalar is left out above because the manual gives two different defaults for it; assign it explicitly with an INTERFACE pragma.
- Vivado IP defaults per C type: scalar ap_none; array ap_memory; pointer ap_none (in) / ap_vld (out) / ap_ovld (inout); reference ap_none (in) / ap_vld (out, inout); hls::stream ap_fifo. Arguments go on s_axilite only when an INTERFACE pragma asks for it (scalars, pointers to scalars, m_axi base addresses, return).
- Paradigms allowed in Vivado IP: scalar/reference register only; array memory or stream; pointer memory, stream or register; hls::stream stream only.
- Block control: ap_ctrl_chain lets a new run start before the previous one ends (throughput); ap_ctrl_hs finishes each run first. Another block protocol can be selected; Vitis accepts all supported ones.
- Check the argument-to-port mapping in the Synthesis Summary, SW I/O Information section.
Also covered in UG1399 Section I: Introduction > Introduction to Vitis HLS Components, p. 17-18.
