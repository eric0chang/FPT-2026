id: HLS-1092
summary: Do not use malloc, alloc, free, or C++ objects created or destroyed dynamically in code to be synthesized; give every array a compile-time size, including function array parameters (`d[16]`, not `d[]`), and use fixed-size, bounded storage declared in the design.

Hardware has to be self-contained, with every resource known at synthesis time, while heap memory belongs to the OS and is created and released at run time. Since the allocation is part of the functionality, transform it into an equivalent bounded representation rather than simply deleting it.
- Array parameters: the C++ compiler ignores the dimension but Vitis HLS relies on it; an unsized parameter such as `int d[]` stops synthesis with an `SYNCHK-61` error about an array whose size is unknown.
Also covered in UG1399 Ch.4 Arrays Primer > Mapping Software Arrays to Hardware Memory, pp. 83-90.

Source: UG1399 v2023.2, Ch.7 Unsupported C/C++ Constructs > Dynamic Memory Usage, pp. 145-147.
