- Without rewind, successive executions of the loop do not overlap. With it, the first iteration of the next execution can follow right behind the last iteration of the current one, keeping the pipeline continuously busy; it usually restarts at once, though a delay is possible (the GUI shows and explains it).
- A loop placed around a DATAFLOW region gets this overlap of successive executions automatically.
```cpp
void top(int cfg, int *in, int *out) {
  int base = cfg * 2;          // initialization: runs once, no branches
  run: for (int i = 0; i < 64; i++) {
#pragma HLS pipeline II=1 rewind
    out[i] = in[i] + base;
  }
}
```
Also covered in UG1399 Ch.3 Loops Primer > Rewinding Pipelined Loops for Performance, pp. 65-66.
