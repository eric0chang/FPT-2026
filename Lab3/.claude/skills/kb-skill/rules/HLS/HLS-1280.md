In `(a, b)` the first operand fills the high bits; `a.concat(b)` likewise places its argument `b` in the low bits.
```cpp
ap_uint<4> hi = 0xA;
ap_uint<4> lo = 0x5;
ap_uint<8>  w = (hi, lo);              // 0xA5
ap_uint<12> x = (ap_uint<4>(3), w);    // literal cast first -> 0x3A5
(hi, lo) = ap_uint<8>(0x3C);           // hi = 0x3, lo = 0xC
```
The manual names uncast native operands as a cause of unexpected concatenation results.

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > Bit-Level Operations, p. 688.
