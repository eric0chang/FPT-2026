summary: Vitis HLS inlines some functions itself (small ones, and those called in a loop pipelined at II=1, also when PERFORMANCE infers II=1); an inlined function's pragmas are ignored and it vanishes from RTL files, reports and Function Call Graph. Put INLINE off in a function that must keep its module.

- Inlining dissolves the function into its caller: it is no longer a separate RTL hierarchy level, its logic and cost are counted inside the caller, and every pragma or directive attached to it is dropped. This holds for an explicit INLINE too.
- Automatic cases named in the manual: small functions, and functions inside any pipelined loop with II=1, including a loop for which PERFORMANCE infers an II=1 pipeline.
- Symptom: a sub-function is missing from the RTL files, per-function reports, Performance Estimates or Function Call Graph, and its own PIPELINE or LATENCY settings have no effect. Only sub-functions that were not inlined get their own RTL file, report file and instance row; the top-level report covers the whole design.
- Each distinct instance of a function appears separately in the Function Call Graph, showing which callees drive a caller's latency and II. Displayed hierarchy can also differ from the source because optimizations may, e.g., turn loops into function pipelines.
- Fix: `#pragma HLS inline off` in that function's body.
Also covered in UG1399 Ch.12 Building and Running an HLS Component > Running C Synthesis > Output of C Synthesis, pp. 360-368.

Source: UG1399 v2023.2, Ch.16 HLS Pragmas > pragma HLS inline, pp. 521-538.
