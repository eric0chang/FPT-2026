Symptom: C simulation reads unexpected values from an AP-typed array that was assumed to start at zero.
Cause: AP types are classes; a bare declaration leaves the elements uninitialized in every release.
Fix: initialize explicitly. In 2023.2 the brace forms behave like built-in types:
```cpp
ap_int<12> acc[16];        // uninitialized (all releases)
ap_int<12> acc0[16] = {0}; // 2023.2: all zero; older: only acc0[0]
ap_int<12> acc1[16] = {};  // 2023.2: all zero; older: uninitialized
```
Code that must also behave the same on older releases should not rely on the brace forms for full zeroing.
Migrating to 2023.2: if outputs differ from an older release, look first at brace initializers of such arrays.
Also covered in UG1399 Section I: Introduction > Changed Behavior, p. 13.

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > Initialization and Assignment from Constants (Literals), pp. 670-676.
