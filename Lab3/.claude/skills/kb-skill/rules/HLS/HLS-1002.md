- Symptom: results are correct, performance gain is nil.
- Cause: the tool derives the micro-architecture (state machine, datapath, register stages) from clock period, target device and pragmas; the task structure and how the design talks to the outside world come from the designer's C++, so strictly ordered code stays strictly ordered.
- Fix: restructure so that (1) computation starts before the whole input has arrived, (2) successive iterations or functions overlap, and (3) each operation handles several words rather than one.

Source: UG1399 v2023.2, Section I: Introduction > Refactoring C++ Source Code for HLS, pp. 14-20.
