- Instruction-level parallelism: move data in wide words and apply each operation to all lanes at once instead of word by word; in the manual's example each stream token is a 16-word vector, so one multiply or add covers 16 values per transfer.
- N must be a positive integer. Element operations are defined recursively on T, so T (a user-defined type is allowed) needs the matching operators. Subtraction, division, remainder and shifts are non-associative and have no reduce form.
- `hls::vector<int,4> v;` is uninitialized; `= 7` sets every element; an initializer list must supply exactly N values; elements are accessed with `operator[]`.
- `<`, `==` etc. compare lexicographically, so they do not give a per-element mask.
- Storage is contiguous. When `sizeof(T)*N` is a power of 2 the allocation is exactly that size and aligned to it (e.g. `vector<char,8>` on 8 bytes, `vector<int,8>` on 32 bytes); otherwise extra space is allocated (padding) so alignment is possible.
```cpp
#include <hls_vector.h>
hls::vector<int, 8> a = 3;                        // all elements 3
hls::vector<int, 8> b = {0, 1, 2, 3, 4, 5, 6, 7};
hls::vector<int, 8> c = a * b;                    // 8 element-wise products
bool lt = a < b;                                  // lexicographic, one bool
typedef hls::vector<short, 4> v4_t;
void vadd(hls::stream<v4_t> &x, hls::stream<v4_t> &y, hls::stream<v4_t> &z) {
  for (int k = 0; k < 64; k++) {
#pragma HLS pipeline II=1
    z.write(x.read() + y.read());                 // 4 lanes per iteration
  }
}
```
