summary: A non-inlined MULADD/MAC function with a fixed latency (e.g. 2) cannot be matched to a DSP accumulator running at II=1; inline the MAC function so the accumulation can be matched.

- Cause: with the function kept separate at latency 2, the multiplier and adder inputs would both have to be available two cycles ahead of the accumulated result, which conflicts with accumulating every cycle.
- Fix: inline the MULADD/MAC function.
- This is the exception to isolating expressions in non-inlined functions for matching: once such a function has a fixed latency and feeds an II=1 accumulator, inline it instead.

Source: UG1399 v2023.2, Ch.10 Optimizing Techniques and Troubleshooting Tips > Managing Area and Hardware Resources > DSP Multi-Operation Matching, p. 296.
