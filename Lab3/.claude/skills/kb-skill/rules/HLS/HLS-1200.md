- Config: `flow_target=vitis` under `[hls]`; normally chosen at component creation but changeable later. In Tcl, `-flow_target` is a global solution option; every option of `config_sdx` is deprecated.
- The flow target sets the default interface ports and other details of the synthesized design, e.g. the Vitis kernel flow generates AXI interfaces; the Vivado IP flow expects pragmas/directives to be used strictly and exports the result as Vivado IP.
- Unlike Vivado HLS, Vitis HLS infers top-level interfaces itself from each argument's C type, the flow target, the default interface mode and any INTERFACE pragma/directive, so the same code can get different ports in the two flows; review the Defining Interfaces chapter before migrating interface code.
- The HW Interfaces section of the synthesis report shows the interfaces actually generated.
- The chosen part/platform also matters: its hardware resources can widen or restrict implementation choices.
Also covered in UG1399 Ch.31 Migrating from Vivado HLS to Vitis HLS > Default User Control Settings, pp. 803-804.

Source: UG1399 v2023.2, Ch.12 Building and Running an HLS Component > Running C Synthesis > Specifying the Flow Target and General Settings, pp. 354-362.
