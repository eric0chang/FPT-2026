- Defaults: top-level array argument -> RAM interface port (m_axi or ap_memory); local array -> RAM; array passed between sub-functions or loops under DATAFLOW -> PIPO (ping-pong) channel.
- The array must be accessed sequentially to be a FIFO.
- The pragma overrides syn.dataflow.default_channel either way: STREAM makes a FIFO when the default is pingpong, type=pipo forces a PIPO when the default is fifo. A per-variable depth also takes precedence over the global syn.dataflow.fifo_depth / `config_dataflow -depth`, which can stream all arrays in a region.
- Depth: without depth=, the FIFO is as deep as the array. Processes consume samples as they arrive, so a smaller depth usually suffices; when every process produces and consumes one item per cycle (II=1), a large FIFO buys nothing and a small depth (even 1) cuts area. depth only matters for arrays streamed as dataflow channels.
- Top-level array ports: stream them with INTERFACE mode=ap_fifo (then streamed automatically) or axis instead.
```cpp
#pragma HLS stream variable=row_buf depth=1 type=fifo
```
Also covered in UG1399 Ch.16 HLS Pragmas > pragma HLS stream, p. 547.

Source: UG1399 v2023.2, Ch.2 Abstract Parallel Programming Model for HLS > Specifying Arrays as PIPOs or FIFOs, pp. 53-54.
