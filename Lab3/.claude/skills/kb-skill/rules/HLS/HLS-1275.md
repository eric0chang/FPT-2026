Symptom: `if (w)` or `return w;` from a bool function is false although the wide value is non-zero; testbench numbers or values handed to native-typed code are wrong.
Cause: implicit conversion from an ap_[u]int above 64 bits to a built-in integer is not supported and passes through a 64-bit integer; each conversion method returns a native type and loses what does not fit (a double has a 53-bit mantissa).
Fix: call the member conversions explicitly (to_bool(), to_int(), to_long(), to_int64(), ...) instead of implicit or C-style casts, as AMD recommends; pick one at least as wide as the value, and keep wider values in the ap type or print them with to_string().
```cpp
bool any_set(ap_uint<72> w) { return w.to_bool(); }  // not: return w;
```

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > Class Methods and Operators, pp. 680-693.
