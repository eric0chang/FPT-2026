- Compiler flow: needed functions get inlined, shared sub-expressions are pulled out, fanout-free fragments that fit DSP widths are matched, scheduling runs, and BIND_OP finally steers the DSP-or-LUT choice.
- Success depends on data types/bitwidths, coding style, and the pragmas applied.
- Width limits come from DSP48 (UG579) or DSP58 (AM004); Versal DSP58 ports: A 34, B 24, C 58, D 27, P 58 bits. Intermediate results must fit too.
- Pitfall: `p = a*b + c; q = a*b + d;` is not matched, because CSE pulls out `a*b` and gives it fanout. Fix (manual tip): one non-inlined function per expression to match.
```cpp
typedef ap_int<16> s16;
typedef ap_int<40> s40;
s40 madd(s16 a, s16 b, s40 c) {
#pragma HLS INLINE off
  return a * b + c;
}
// p = madd(a, b, c); q = madd(a, b, d);
```

Source: UG1399 v2023.2, Ch.10 Optimizing Techniques and Troubleshooting Tips > Managing Area and Hardware Resources > DSP Multi-Operation Matching, pp. 294-295.
