Symptom: a left shift of a positive value comes back negative or small. Storing the result in a wider variable afterwards does not help - the bits are already gone (the manual's 5.375 in `ap_fixed<8,5>` << 2 gives -10.5 even in an `ap_fixed<25,15>`).
```cpp
ap_fixed<8,4>  x = 3.25;                     // 0011.0100
ap_fixed<16,8> bad = x << 2;                 // -3.0: top bits lost
ap_fixed<16,8> up  = ap_fixed<10,6>(x) << 2; // 13.0
ap_fixed<16,8> dn  = ap_fixed<10,4>(x) >> 3; // 0.40625 (x >> 3 gives 0.375)
```
Shift counts have separate ap_uint (unsigned) and ap_int (signed) overloads. The overview, the Signed Shift Right text and the signed-shift code examples say a negative count shifts the opposite way (x >> -2 acts as x << 2), but the bullets under Signed Shift Left state the reverse; treat a negative count's direction as unreliable and avoid it.

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > Class Methods, Operators, and Data Members > Shift Operators, pp. 712-715.
