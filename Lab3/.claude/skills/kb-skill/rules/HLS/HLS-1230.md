- Without a pragma, HLS chooses each operator's implementation and internal pipelining itself, e.g. an add is LUT-based by default and can be moved into a DSP with impl=dsp.
- `op=mul latency=3` alone asks for a 3-stage pipelined multiplier. Extra stages give RTL synthesis registers it may use for post-route timing: registers on the operation output mainly help the output datapath, registers on its input help the input datapath and the FSM control logic. More stages also mean more cycles for that operation.
- BIND_STORAGE does the same for storage; the operator configuration commands give every instance of one operation type the same pipeline depth. Available impl values are listed in the BIND_OP / BIND_STORAGE pragma reference.
```cpp
int mac(int x, int k, int acc) {
  int prod;
#pragma HLS bind_op variable=prod op=mul impl=fabric latency=2
  prod = x * k;        // fabric multiplier, 2 stages
  return prod + acc;   // adder left to HLS
}
```
