- Symptom: more copies of a loop body than the code requested after partitioning, reshaping or aggregating.
- Cause: HLS replicates hardware so the whole widened data can be consumed in one clock cycle.
- Fix: adjust automatic unrolling through config_unroll; e.g. `syn.unroll.tripcount_threshold=16` lets only loops with fewer than 16 iterations be unrolled automatically, and only if that raises throughput.
Also covered in UG1399 Ch.4 Arrays Primer > Array Accesses and Performance > Array Reshaping, p. 89.
Also covered in UG1399 Ch.6 Data Types > Structs, p. 109.
