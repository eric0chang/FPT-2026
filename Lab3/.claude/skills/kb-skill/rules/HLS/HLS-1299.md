- Each float/double conversion in the C code is implemented as a converter unit in hardware: `float r = sqrt(x);` becomes converter -> double square root -> converter, while `sqrtf(x)` maps to one single-precision core. Dropping the converters saves area and improves timing.
- Precision follows the C type: `double` multiply, add and divide map to 64-bit double-precision floating-point IP cores. Mixing half, float and double operands likewise inserts type-conversion hardware.
- C++ `<cmath>` overloads `sin`, `cos`, etc. for float and double, and the f-suffixed forms map to 32-bit operations; besides the overloaded `func`, the HLS math library offers `funcf` (single only) and `half_func` (half only).
- Seven functions (copysign, fpclassify, isinf, isfinite, isnan, isnormal, signbit) may also behave differently in C sim depending on the C standard and system headers.
- Recommended compile options: `-std=c99` for C sources and `-fno-builtin` for C and C++, passed with `add_files -cflags`.
- These errors often appear when porting C code to C++.
- float and double are synthesized with only partial IEEE-754 compliance (PG060).
Also covered in UG1399 Ch.6 Data Types > Floats and Doubles, pp. 104-106.

Source: UG1399 v2023.2, Ch.22 HLS Math Library > Common Synthesis Errors, pp. 724-734.
