Integer literals are handled by the C++ compiler and host, which typically caps them at 64 bits (`LL`/`ULL`). The string constructors take a digit string of any length up to the variable width; the radix (2, 8, 10 or 16) goes in the second argument, or a `0b`/`0o`/`0x` prefix marks it.
Manual conflict: it says literals work up to that 64-bit limit, yet also states that ap_[u]int wider than 53 bits must be initialized from a string (and the example given for that is malformed: missing `>`, a decimal string with a fraction and no radix). A string is correct under both readings.
Without a radix the string is read as hex, so "1010" means 0x1010, not ten.
```cpp
ap_uint<128> key("0123456789abcdef0011223344556677", 16);
key = ap_uint<128>("ffeeddccbbaa99887766554433221100", 16); // cast to assign
ap_uint<8> m("11001010", 2);   // binary
ap_uint<8> n("0xCA", 16);       // prefixed form
ap_int<40> small = -5;          // fits a literal: sign-extended to 40 bits
```

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > Initialization and Assignment from Constants (Literals), pp. 676-677.
