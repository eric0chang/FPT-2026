Other access patterns cause functional failures. Writing `out[i] = in[i]` and then updating `out[i].field`, or copying member by member from `in[i]` to `out[i]`, are the manual's bad examples.
Arrays allow random or repeated access while a stream must be consumed in sequence, so mixing the two styles leads to coding and synthesis problems. hls::stream arguments enforce streaming semantics in the source, which is why they are the recommended form for any streaming interface.
```cpp
struct Pkt { short tag; int val; };
void k(Pkt src[N], Pkt dst[N], bool bump) {
#pragma HLS INTERFACE mode=ap_fifo port=src
#pragma HLS INTERFACE mode=ap_fifo port=dst
  for (unsigned n = 0; n < N; n++) {
    Pkt p = src[n];          // one whole-struct read
    if (bump) p.val += 1;
    dst[n] = p;              // one whole-struct write
  }
}
```
Also covered in UG1399 Ch.4 Arrays Primer > Arrays on the Interface > FIFO Interfaces, pp. 92-93.

Source: UG1399 v2023.2, Ch.8 Interfaces of the HLS Design > Coding Style for Array to Stream, pp. 199-200.
