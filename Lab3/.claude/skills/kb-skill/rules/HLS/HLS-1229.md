id: HLS-1229
summary: Avoid BIND_OP impl=dsp on operators you expect HLS to fuse into DSP multi-op patterns (MULADD, AMA, ADDMUL and subtract forms): BIND_OP takes no part in that matching and can block it. If a pipelined MAC loop's mul-add isn't matched, drop that BIND_OP and add EXPRESSION_BALANCE off.

- Symptom: an expression such as a*b+c is not mapped as one combined DSP operation.
- BIND_OP case: a MAC function computing `acc = d*c + acc` that bound its multiply to a DSP (BIND_OP on `acc`, op=mul, impl=dsp, 2-cycle latency) kept the compiler from recognising the MULADD; removing the pragma let it assign the MULADD to a DSP.
- Expression-balance case: PIPELINE unrolls the inner MAC loop and balances the resulting expression, which also blocks matching; turning balancing off in that region improves it.
```cpp
acc_t mac(data_t d, coef_t c, acc_t a) { return d * c + a; }  // no BIND_OP
void fir(const data_t win[NT], const coef_t h[NT], acc_t *y) {
#pragma HLS EXPRESSION_BALANCE off
#pragma HLS PIPELINE II=1
  acc_t s = 0;
  TAPS: for (int t = 0; t < NT; t++)
    s = mac(win[t], h[t], s);
  *y = s;
}
```
