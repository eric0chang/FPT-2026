- The generated RTL is the same either way; the HLS math library only changes what C sim computes so that it equals the hardware result.
- Option A: `#include "hls_math.h"` and swap calls such as `sinf` for `hls::sinf`; the `hls` namespace functions are drop-in replacements for the `std` ones.
- Option B (no source edits): copy `lib_hlsm.cpp` from the `src` folder of the Vitis HLS installation into the project and add it as an ordinary design file.
- Trade-off: C sim results now differ from earlier standard-library runs, so still validate them against a software reference with a tolerance-based test bench. Example: `fmin`/`fmax` do not yet implement TS 18661-1 sNaN handling, so sNaN inputs can give results that differ from glibc 2.25 or later.

Source: UG1399 v2023.2, Ch.22 HLS Math Library > Verification Options 2 and 3, pp. 724-733.
