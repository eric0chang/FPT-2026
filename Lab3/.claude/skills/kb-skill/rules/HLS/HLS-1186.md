- Data should normally flow from each task to the next one; a channel that bypasses a task can limit dataflow performance.
- Typical shape: the first process writes arrays X and Y, a middle process consumes Y, and the last process reads X plus the middle output; X is the array to deepen.
- The deeper buffer holds the data for the later consumer while the task in between is still running.
- With type=pipo, depth counts blocks (whole array buffers), so each extra unit costs one more array's worth of memory.
- Example: `#pragma HLS STREAM type=pipo variable=skip_buf depth=3` for a buffer produced by task 1 and consumed by task 3.
- Channel sizing matters the same way elsewhere: mismatched FIFO/PIPO depths can create unintended synchronization points inside the region through back pressure.
Also covered in UG1399 Ch.2 Abstract Parallel Programming Model for HLS > Specifying Arrays as PIPOs or FIFOs, pp. 53-54.

Source: UG1399 v2023.2, Ch.10 Optimizing Techniques and Troubleshooting Tips > Limitations of Control-Driven Task-Level Parallelism > Bypassing Tasks and Channel Sizing, pp. 299-300.
