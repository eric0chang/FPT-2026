summary: Since 2022.2, reading an empty hls::stream in C sim is an error (a deadlock error when hls::task is used), and unread leftover data gives a warning; both signal possible RTL sim hangs. Debug the blocked read; add -DHLS_STREAM_READ_EMPTY_RETURNS_GARBAGE only if empty reads are intended.

- Including `hls_task.h` makes reads on `hls::stream` and `hls::stream_of_blocks` block in C sim, so code that relied on reading an empty stream now deadlocks in simulation.
- Messages: without tasks, `an hls::stream is read while empty`; with tasks, `deadlock detected when simulating hls::tasks`. Run C sim in debug mode and inspect where `read()` calls are stuck.
- The cflag downgrades the error to a warning; empty reads then return the type's default value.
- Name streams, e.g. `hls::stream<int> coef("coef_in");`, so leftover-data warnings identify the stream instead of an auto-generated name.

Source: UG1399 v2023.2, Ch.25 HLS Task Library > Simulation and Co-simulation, pp. 738-755.
