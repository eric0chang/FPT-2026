Symptom: `?` in the latency/interval (or trip count) columns of the Synthesis Summary; changing LOOP_TRIPCOUNT later changes these reported numbers but not the RTL.
Cause: the bound comes from, say, a top-level argument or a dynamically computed variable, so HLS knows the latency of one iteration but not how many iterations run; loop and overall latency are unknown.
Fix (reporting): put `#pragma HLS LOOP_TRIPCOUNT max=32` (and/or `min=`, `avg=`) inside the loop body; in the manual's example the report then showed trip count 0 ~ 32 and best/worst-case latency 2/34, so solutions can be compared. Use other directives to actually change the design.
Fix (hardware): an `assert` limiting the loop variable is used both for reported limits and to build hardware exactly sized to them. Unlike tripcount values, asserts influence synthesis; because HLS takes the asserted condition as given, an assert that can be violated misleads the tool.
Note: p.81 says tripcount values serve only reporting or the PERFORMANCE pragma; the other pages simply say LOOP_TRIPCOUNT has no impact on synthesis.
