- ap_fifo saves the address logic of ap_memory/bram. Random access needs ap_memory or bram; rejected pattern: one ap_fifo pointer read at p[0], then p[2], then p[-1].
- When the order cannot be analysed HLS only emits `XFORM-124` ('may have improper streaming access(es)'), so check the synthesis log and treat that warning as a cue to verify the access order. For an indexed read like `y[i] = x[sel[i]]` on FIFO ports, HLS assumes the indices are 0, 1, 2, ..., so the `sel` array is never read; the result is right only if the indices really are sequential, otherwise RTL/co-simulation mismatches and the design can fail at runtime.
- An ap_fifo array is read in the same order it was written (first in, first out).
- ap_fifo works for arrays, pointers and references: inputs stall while <in>_empty_n is Low, outputs while <out>_full_n is Low.
- For pointers read or written several times on such ports, see the volatile guidance in Multi-Access Pointers on the Interface.
- With the top function or top-level loop pipelined with rewind, HLS adds a _lwr output that goes High when the last FIFO write completes.
Also covered in UG1399 Ch.4 Arrays Primer > Arrays on the Interface > FIFO Interfaces, pp. 91-92.

Source: UG1399 v2023.2, Ch.8 Interfaces of the HLS Design > Port-Level I/O: Memory Interface Protocol, pp. 204-213.
