summary: If C simulation runs out of memory or crashes with very large local arrays (worse with ap_int/ap_fixed types), the arrays sit on the stack: enlarge it via syn.csimflags, or heap-allocate them for simulation only under `#ifndef __SYNTHESIS__`.

- Cause: local arrays live on the limited stack, not on the OS-managed heap that can grow. Arbitrary-precision and especially fixed-point C++ types need more memory to model than native types; PCs often have less memory than big Linux servers.
- Fix 1: raise the stack with a linker flag, e.g. `syn.csimflags -z stack-size=10485760`; useless if the machine itself lacks memory.
- Fix 2 (keep the fixed-size array for synthesis):
```cpp
#ifdef __SYNTHESIS__
  ap_int<32> big[NBIG];
#else
  ap_int<32> *big = (ap_int<32> *)malloc(NBIG * sizeof(ap_int<32>));
#endif
```
- Cost of fix 2: simulated and synthesized code now differ, so the test bench must exercise every array access, and RTL co-simulation is what confirms the real memory accesses.

Source: UG1399 v2023.2, Ch.4 Arrays Primer > C Simulation with Arrays, pp. 96-97.
