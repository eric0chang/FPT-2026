summary: When a function is called with different constant values for one argument, apply FUNCTION_INSTANTIATE variable=<arg> (plus INLINE off so a small function is not auto-inlined) to get one constant-specialized RTL block per call with simpler control logic instead of one shared generic block.

- Without it, the calls share one identical implementation (at the same hierarchy level, one RTL block: least area) whose control logic must handle every call's argument values.
- With it, each instance is optimized for its constant, cutting area and possibly improving latency and throughput, while the function hierarchy is kept.
- HLS auto-inlines small functions even when they are instantiated; `INLINE off` keeps the hierarchy. The Ch.5 example uses it without stating it as a requirement.
- Useful when calls sit at different hierarchy levels: when sharing would need heavy inlining or code changes, several small specialized copies beat several large copies that can't be shared anyway.
```cpp
int step(int v, int k) {
#pragma HLS INLINE off
#pragma HLS FUNCTION_INSTANTIATE variable=k
  return v + k;
}
// top: r0 = step(a, 0); r1 = step(b, 2); r2 = step(c, 50);
```
Also covered in UG1399 Ch.16 HLS Pragmas > pragma HLS function_instantiate, p. 520.
