- Blocking `read()`/`write()` check empty/full themselves and behave identically in C sim and co-sim when used in these patterns: (1) plain reads with conditional writes; (2) a process that tests `empty()`/`full()` and returns before any side effect (stream, memory or static-variable access).
- Other uses of the blocking API can be non-deterministic.
```cpp
void stage(hls::stream<int> &in, hls::stream<int> &out) {
  if (in.empty()) return;   // no side effect before this test
  out.write(in.read() * 3);
}
```
