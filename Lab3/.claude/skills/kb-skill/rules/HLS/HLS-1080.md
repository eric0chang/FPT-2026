Globals of any kind (scalars, arrays) may be used freely inside the design. For data that crosses the kernel boundary, such as an input and an output array, list them in the top-level argument list instead of reaching them as globals.
- RTL ports come from the top function's arguments and return value (together with flow_target, config_interface defaults and INTERFACE pragmas), so a global read and written only inside the design becomes internal storage with no I/O port; to observe or drive it from outside, add it to the argument list and give it an INTERFACE mode there.
- Migration: Vivado HLS could export globals on the top-level interface; Vitis HLS cannot, and using `-expose_global` makes it stop with an error.
```cpp
int gain;                 // global: stays internal
void top(int g, int *o) { // expose it as an argument instead
  gain = g;
  *o = gain * 2;
}
```
