- Blocking: a read of an empty channel or a write to a full one stalls that process, so results do not depend on timing; the cost is possible deadlock from too-small FIFOs or differing production/consumption rates.
- Non-blocking access without a status check: reading an empty channel returns uninitialized data or repeats the last item, and writing a full one may lose the item.
- `read_nb`/`write_nb` return true on success; on false the stream is untouched, so the code needs an explicit no-transfer path.
- Non-determinism comes from reading an empty FIFO or writing a full one. Full never happens in C sim (streams are unbounded); it only appears in RTL simulation with real FIFO sizes.
- With block-level protocol `ap_ctrl_none` and any non-blocking stream use, C/RTL co-sim is not guaranteed to complete.
- Exception: a process that only tests `empty()`/`full()` and returns before any side effect still counts as blocking-only (deterministic).
- Typical use: error handling when RTL FIFOs are full or empty, e.g. try a second input stream if the first has nothing.
Also covered in UG1399 Ch.2 Abstract Parallel Programming Model for HLS, p. 41-42.

Source: UG1399 v2023.2, Ch.23 HLS Stream Library > Non-Blocking API, pp. 741-744.
