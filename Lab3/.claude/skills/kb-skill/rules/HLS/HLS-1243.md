- Long serial chains (repeated `+=`/`*=`, or an unrolled accumulation loop) add latency, especially with a short clock period. Balancing relies on associativity and commutativity so independent operations run in parallel; it may cut latency but costs extra hardware and prevents operator sharing, so turn it off when area matters more.
- `#pragma HLS expression_balance` acts on the region/function where it is placed; add `off` to disable it.
- Float/double: rounding/truncation and saturation make regrouping change values (`(b*c)*(e*f)` and `(b*f)*(e*c)` need not give identical results), so HLS keeps the source order; full or partial unrolling of a float computation may then not yield the expected parallel hardware. config_compile -unsafe_math_optimizations lifts this restriction, but results are no longer guaranteed to match C simulation exactly.
Also covered in UG1399 Ch.10 Optimizing Techniques and Troubleshooting Tips, pp. 255-256.
