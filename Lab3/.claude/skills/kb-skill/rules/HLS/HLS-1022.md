---
id: HLS-1022
summary: Do not rely on source order between accesses to different hls::streams: the scheduler may move a write to one stream before or after a read from another. Only accesses to the same stream are kept sequential.
tags:
  - group:hlskb
  - hls-stream
  - ordering
  - scheduling
  - tool:vitis-hls
  - type:must-not
records: []
---
- Each stream behaves as a FIFO that is read and written sequentially; once an item has been read it cannot be read a second time.
- Ordering across distinct streams is a scheduler decision, not something the code order guarantees.

Source: UG1399 v2023.2, Ch.2 Abstract Parallel Programming Model for HLS > Data-driven Task-level Parallelism, pp. 44-45.
