Cause: 2023.2 changed brace initialization of ap_[u]int/ap_[u]fixed arrays to zero every element (older releases zeroed at most element 0). The tool counts these zero stores as one more writer of the array, which the dataflow checks can reject.
Fix (inferred; the manual names only the cause): a bare declaration stays uninitialized in all releases and so adds no initialization write. Keep an explicit initializer only where the code actually reads the zeros.

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > Initialization and Assignment from Constants (Literals), p. 676.
