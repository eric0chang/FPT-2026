- A `yes` in the Pragma column marks a user-forced mapping; an empty cell means the tool inferred it.
- Bind Op covers ops of interest (arithmetic, floating point, DSP): fabric (LUT) vs DSP choice, latency, DSP count by hierarchy, and a link to the source line.
- Bind Storage gives BRAM/URAM counts and per-variable storage type, implementation and latency; BIND_STORAGE can choose a memory type (e.g. single or dual port), an implementation (BRAM, LUTRAM, URAM, SRL, ...) and a latency.
- A second table in each report lists global config settings that also alter allocation (e.g. `dadd` forced to fulldsp, `ddiv` latency fixed to 2).

Source: UG1399 v2023.2, Ch.12 Building and Running an HLS Component > Running C Synthesis > Synthesis Summary > Bind Op and Bind Storage Reports, pp. 366-367.
