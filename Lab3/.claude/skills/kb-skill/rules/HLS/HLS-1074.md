Native C/C++ types only exist in 8-bit steps, so an operation needing another width is built at the next native size: a 10-bit input is carried as 16 bits, an 18-bit result as 32 bits, widening the whole datapath.
- Narrow operators cost less area, have shorter delay, can need fewer cycles and allow a higher clock; a 32-bit int multiply can need more than one DSP cell, while a 17-bit one sized with ap_int is no longer built at 32 bits.
- Output sizing example: a sum of a 6-bit and a 12-bit input fits in 13 bits, not 32.
- In the manual's mul/add/div/mod example, moving to exact AP widths cut latency from 66 to 35 cycles and area by about 75%; the multi-cycle divide and remainder drove most of the latency gap.
- Check the narrowed types in C simulation first (the types are bit-accurate, so C sim shows whether results stay identical or acceptably close), then compare the latency and utilization tables of the synthesis report.
Also covered in UG1399 Ch.20 Arbitrary Precision Data Types Library > C++ Arbitrary Precision Integer Types, pp. 669-673.

Source: UG1399 v2023.2, Ch.6 Data Types > Arbitrary Precision (AP) Data Types, pp. 124-127.
