summary: For data that enters or leaves sequentially from a streaming source (another kernel, a video processor), prefer axis over m_axi: no address logic, bursts of unlimited length, fewer resources. Keep m_axi for addressed global memory (DDR/HBM/PLRAM) shared with the host or other kernels.

- axis: one unidirectional channel with a ready/valid handshake; data passes to the next axis interface without an address.
- m_axi: independent read and write channels, bursts of up to 4 KB per address phase, a queue of outstanding transactions, optional cache; the adapter costs more logic.
- The choice follows where the data lives: a streaming producer/consumer fits axis, data held in global memory needs a memory-paradigm interface.

Source: UG1399 v2023.2, Ch.8 Interfaces of the HLS Design > AXIS Interfaces in the Vivado IP Flow, pp. 154-163.
