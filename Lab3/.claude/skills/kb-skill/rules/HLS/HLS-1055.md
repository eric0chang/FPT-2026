summary: INLINE dissolves a function into its caller so its logic is optimized and shared with the caller's (small functions inline automatically; INLINE off keeps a module, recursive flattens all below); a multiply-called function then loses its shared instance, which can grow area. Avoid huge functions.

- A function that is not inlined becomes a separate RTL module; `#pragma HLS INLINE off` prevents the tool's automatic inlining of a small function.
- The `recursive` option inlines every function below the target; applied to the top-level function it removes all hierarchy.
- Gain: after inlining, the function's operations can be optimized and shared together with the calling function's operations; inlining small, rarely called functions folds their resources into the caller, which may allow common resources to be shared.
- Cost: there is no single reusable instance any more; each call site in the parent gets its own logic, which can raise area. Compare resource use with and without the pragma before keeping it.
- Size: avoid creating very large functions, by hand or through inlining; large functions tend to have non-trivial control paths that are hard for the tool to process, while smaller functions with simple control paths implement better on FPGA.
- Because INLINE reshapes the architecture without editing the source, it is a handy knob for architecture exploration.
