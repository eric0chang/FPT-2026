- Latency already within [min, max]: accepted, no further optimization.
- Below min: extended to min with dummy clock cycles; potential gain is more resource sharing.
- Above max: HLS raises effort; if it still fails it warns and keeps the smallest latency it reached, above max. Look for this warning in the synthesis log.
- By default the tool hunts for the highest throughput, lowest latency and smallest area; constraining loops, functions or regions limits the solutions explored there, and the fewer degrees of freedom it has, the faster it finishes.
Also covered in UG1399 Ch.12 Building and Running an HLS Component > Running C Synthesis > Improving Synthesis Runtime and Capacity, p. 360.
