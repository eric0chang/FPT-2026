- This is the canonical form AMD recommends; variable initialization (constructors included) and expressions passed by value to processes fall outside it, and non-canonical code is only implemented best-effort.
- The called sub-functions may themselves contain function- or loop-level dataflow.
- The dataflow checker (Vitis unified IDE, v++) reports deviations; syn.dataflow.strict_mode is warning by default and can be set to error or off.
- For non-canonical regions, confirm overlap and performance in the dataflow viewer and the cosim timeline trace.
```cpp
void region(const int a[64], int z[64]) {
#pragma HLS dataflow
  int t0[64], t1[64];
  stage_a(a, t0);
  stage_b(t0, t1);
  stage_c(t1, z);
}
```

Source: UG1399 v2023.2, Ch.2 Abstract Parallel Programming Model for HLS > Canonical Forms, pp. 50-52.
