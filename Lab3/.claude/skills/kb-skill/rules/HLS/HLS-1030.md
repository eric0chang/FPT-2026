- The tool can misestimate the start FIFO default; scalar FIFOs take their default from syn.dataflow.fifo_depth.
- Start FIFOs can instead be removed for one region with `#pragma HLS DATAFLOW disable_start_propagation`, at your own risk: only when unbounded producer/consumer slack is wanted and the processes may run indefinitely, controlled purely by their FIFO/PIPO channels.
- DATAFLOW connects tasks with ping-pong RAM or FIFO channels; start FIFOs are additional, compiler-inserted channels.
Also covered in UG1399 Ch.16 HLS Pragmas > pragma HLS dataflow, p. 512-513.

Source: UG1399 v2023.2, Ch.2 Abstract Parallel Programming Model for HLS > Specifying Compiler-Created FIFO Depth, pp. 56-57.
