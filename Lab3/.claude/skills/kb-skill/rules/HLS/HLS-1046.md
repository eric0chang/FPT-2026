- Symptom: `WARNING: [SCHED 69]` for a `load` on the array, often with 'resource limit of core:RAM:<array>:p0 is 1', then `Target II: 1, Final II: 2`. HLS relaxes the II on its own and reports what it reached.
- Cause: a non-interface array is mapped to block RAM, which offers at most two data ports; a single-port RAM allows one read or one write per cycle. Reading `a[i]`, `a[i-1]` and `a[i-2]` in one iteration needs three ports, so even dual-port RAM cannot give II=1. The same happens when unrolling, or pipelining an outer loop, makes parallel operations read an unpartitioned array: data bandwidth must match the operations meant to run in parallel.
- Fix: locate the bottleneck from the source line the message cites (or in the Analysis view), then reduce the need for more than two ports or add ports: split the array into several smaller RAMs with ARRAY_PARTITION (more ports in total), use ARRAY_RESHAPE, or rewrite the loop so it reads the array only once per iteration.
- Cost: splitting the array completely into registers (e.g. 400 elements read in one cycle) gives full access at a very significant hardware cost, so match the partitioning to the parallelism actually needed.
