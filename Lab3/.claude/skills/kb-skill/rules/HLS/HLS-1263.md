summary: Mark a DATAFLOW region argument with `#pragma HLS stable variable=<v>` if, while the region runs, nothing overwrites what it reads or reads what it writes first (e.g. config ports changed only while idle): its task-level sync is dropped, so iterations overlap and II improves. Control-driven only.

- STABLE tells HLS the value holds during execution but is not a constant to optimize away, and its fanout needs no registers.
- Without it, a later process that reads the argument joins the region's start synchronization, so the first process cannot restart until that one is ready again, which blocks iteration overlap. With it, the first process need not read such an input nor the last process write such an output.
- Correctness rests on your guarantee; the compiler simply assumes it. Typical safe case: the caller touches the variable only before the region starts or after it completes.
- Data-driven task-level parallelism cannot detect when the kernel is idle, so STABLE does not apply there.
```cpp
void region(int cfg[8], int *d) {
#pragma HLS stable variable=cfg
#pragma HLS dataflow
  stage_a(d);
  stage_b(cfg, d);
}
```
Also covered in UG1399 Ch.2 Abstract Parallel Programming Model for HLS > Stable Arrays, p. 57.
