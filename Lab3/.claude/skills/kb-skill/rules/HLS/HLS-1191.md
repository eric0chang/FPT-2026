- Reaching good QoR involves repeated restructuring of the source; an early verification flow catches functional regressions introduced by each change.
- The tool never inspects outputs itself: a non-zero return fails csim or cosim (`SIM 211-100 ... nonzero return value`), even when the RTL outputs are right, while a zero return is reported as a pass whatever the run produced.
- Cosim reuses this checking code: the C test bench runs and the top function's arguments are recorded as input vectors, the RTL is simulated with those vectors, and its outputs are handed back to the test bench's `main()` for checking.
- Compare per element against expected arrays, or write results to a file and diff it against a golden file; either style is valid.
- Different non-zero codes may encode different failure kinds; keeping the value within 8 bits is recommended because the OS/Tcl shell interprets it.
- Why first: C executes orders of magnitude faster than RTL simulation, so prove the function in C before synthesizing it.
```cpp
int main() {
  int errs = 0;
  for (int t = 0; t < N_TESTS; t++) {   // stim/ref loaded from files
    my_top(stim[t], &res);
    if (res != ref[t]) errs++;
  }
  printf(errs ? "FAIL\n" : "PASS\n");
  return errs ? 1 : 0;
}
```
