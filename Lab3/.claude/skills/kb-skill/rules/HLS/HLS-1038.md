Cause: a true (RAW) dependence through memory between iterations (distance 1): iteration i stores mem[i+1], iteration i+1 loads it, so the load waits for the store and for the multi-cycle operation that feeds it.
- Store a product built from the previous iteration's load into mem[i+1], then load mem[i]: Final II 2.
- Load mem[i], multiply, store mem[i+1] in one iteration, so all three are chained across iterations: Final II 4.
A higher clock frequency deepens the operators (more latency) and pushes II up further.
By contrast, in the manual's scalar case (a product consumed by the next statement) HLS removes the RAW with data forwarding and the pipelined function reaches II=1.
Check: the `Pipelining result: Target II ..., Final II ...` line in the log.

Source: UG1399 v2023.2, Ch.3 Loops Primer > Managing Pipeline Dependencies, pp. 64-71.
