- Default: loops stay rolled, with one set of hardware reused by every iteration.
- Full unroll: one parallel copy of the body per iteration and the loop disappears, so all iterations can run concurrently; in the manual's 10-iteration accumulate example latency dropped sharply while FF and LUT counts rose.
- Partial unroll (`factor=F`): the body is duplicated F times and the trip count is divided by F (10 → 5 for F=2), a compromise when the device cannot afford full copies.
- F need not divide the trip count: HLS then inserts an exit check so the partially unrolled loop behaves like the original; when it divides evenly the check is omitted.
Also covered in UG1399 Ch.16 HLS Pragmas > pragma HLS unroll, pp. 550-551.

Source: UG1399 v2023.2, Ch.3 Loops Primer > Unrolling Loops, pp. 74-75.
