The manual highly recommends this style: signatures use names such as `din_t`/`dout_t` and only the header changes when switching to `ap_int<N>`; widths can be refined for area and performance without editing function bodies.
- Gain: portability and readability; bench-only constants such as the transaction count can sit in the same header, since design and bench both include it.
```cpp
// types.h
#include "ap_int.h"
typedef ap_int<10> sample_t;  // previously: short
typedef ap_int<18> acc_t;     // previously: int
```
Re-run C simulation after each width change to confirm the results remain identical or acceptable.
Also covered in UG1399 Ch.12 Building and Running an HLS Component > Running C Simulation > Example Test Bench, pp. 340-341.

Source: UG1399 v2023.2, Ch.6 Data Types > Arbitrary Precision (AP) Data Types, p. 125.
