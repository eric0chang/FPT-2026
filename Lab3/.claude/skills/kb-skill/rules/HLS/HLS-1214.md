summary: C sim treats streams as unbounded, so a too-shallow FIFO (hls::stream default depth 2, or a dataflow channel) shows only as a cosim/hardware stall or deadlock: outside DATAFLOW a stream must hold all producer output (XFORM 203-733); set STREAM depth from rates, or start at the item count and shrink.

- Mechanism: a full FIFO blocks its producer; if the consumer is meanwhile waiting on another channel the producer has not written yet (e.g. a PIPO), nothing moves. Manual example: proc_1 pushes 10 items into a FIFO before writing the PIPO proc_2 needs, so that FIFO needs depth >= 10. Blocking accesses can deadlock on too-small streams.
- Outside DATAFLOW each sub-function or loop finishes before the next starts, so nothing drains the FIFO while the producer writes; ERROR XFORM 203-733 names the offending stream. The manual's first suggestion is a DATAFLOW region for stream-connected tasks; otherwise resize with `#pragma HLS stream` or `set_directive_stream`.
- Rate changes (interpolation, decimation): analyze the rates; depth 2 suffices for most sample-at-a-time streaming but can be too small where a stage raises the data rate.
- Detection is on by default: cosim stops with `DEADLOCK DETECTED` and lists each dependence cycle with process and channel states (`FULL`/`EMPTY`); the Dataflow Viewer highlights them and cross-probes to source.
- A user-set depth replaces the throughput-oriented value the tool computes. The resulting deadlock never shows in C simulation, only in cosim or in the full system.
- Sizing: begin with depth = the number of values transferred (e.g. the array size), confirm cosim passes, then reduce and recheck; a failure after a reduction means that FIFO is too small. Set depth per channel with STREAM depth, or as the default with syn.dataflow.fifo_depth.
- Isolating size problems: rerun with default ping-pong buffers, then with no explicit FIFO sizes (channel then defaults to the C array size), then shrink FIFOs until cosim stalls.
- The cosim Dynamic Deadlock Prevention option tunes FIFO channel sizes automatically during co-simulation. The GUI can also plot each FIFO/PIPO occupancy over time after cosim to help pick depths.
- The manual is inconsistent on `hls::stream<T, Depth>`: p.735 calls Depth the FIFO depth, p.738 the depth of the co-sim verification adapter FIFO; p.741 also mentions a default size of 1. Safe action: set the RTL depth explicitly with the STREAM pragma.
```cpp
hls::stream<short> up4x;
#pragma HLS STREAM variable=up4x depth=32  // depth from your rate analysis
```
