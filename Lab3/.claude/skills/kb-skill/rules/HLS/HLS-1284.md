id: HLS-1284
summary: In an expression that combines an ap_[u]fixed value with a numeric literal through an operator, cast the literal to an ap_[u]fixed type first (x + T(0.25)); left bare, it is taken as int/float/double and the compiler may find no suitable operator.

Plain initialization or assignment from a literal is fine; the problem appears only when the literal is an operand.
```cpp
typedef ap_ufixed<12,6,AP_RND,AP_SAT> gain_t;
gain_t g = 1.5;            // OK: initialization
g = g - gain_t(0.125);     // OK: literal converted first
// g = g - 0.125;          // operator lookup may fail
```
The manual's test bench steps its stimulus values this way inside the loop.

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > ap_[u]fixed example and test bench, pp. 696-697.
