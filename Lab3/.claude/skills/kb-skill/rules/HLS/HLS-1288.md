Symptom: operands or the target variable are declared with AP_RND/AP_SAT, yet intermediate results are not rounded or clamped where expected.
Cause: operators compute in a result type wide enough for the full result; Q/O/N only matter in the conversion into the left-hand-side type.
Fix: break the expression with a typed intermediate variable wherever rounding or saturation must take effect.
```cpp
typedef ap_fixed<8,4,AP_RND,AP_SAT> s_t;
s_t a, b, c;
s_t t = a * b;     // rounded + saturated here
s_t y = t + c;     // and again here
// s_t y = a*b + c; // only once, on the final sum
```
For hls_math, the manual does not say whether a Q/O/N-qualified argument is rejected or its modes are ignored; either way, put the modes on the variable that receives the function's result.
Also covered in UG1399 Ch.6 Data Types > Overview of Arbitrary Precision Fixed-Point Data Types, p. 129.
