Symptom: an unsigned destination gets its upper bits set, or a narrowed value flips sign.
Cause: the destination's signedness plays no part; extension follows the source expression, and truncation keeps only the low bits with no sign handling. For `&`, `|`, `^` the expression is signed unless both operands are unsigned, so one signed operand is enough to sign-extend.
Fix: cast the source (or an operand) to the signedness and width you want.
```cpp
ap_int<4>   t = -2;             // 1110
ap_uint<4>  k = 0xC;            // 1100
ap_uint<12> a = t;              // 0xffe: sign-extended
ap_uint<12> b = ap_uint<4>(t);  // 0x00e: zero-padded
ap_uint<12> c = t & k;          // signed 4-bit 1100 -> 0xffc
ap_int<9>   w9 = 200;           // 0x0c8
ap_int<8>   w8 = w9;            // keeps 0xc8 -> -56
```

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > Expressions Involving ap_[u]<> types, pp. 679-683.
