Unpipelined, an iteration begins only once the prior one is done, so cycles ≈ trip count × per-iteration latency (20 iterations × 3 cycles = 60).
With PIPELINE a new iteration can start every II cycles; II=1 is the ideal of one new iteration per clock. In the manual's read/compute/write illustration the gap between reads went from 3 cycles to 1 and the last write came at cycle 4 instead of 8, with no extra hardware.
Data dependencies inside the loop can make II=1 unreachable, so the achieved II may be larger than requested.
Any loop nested inside the pipelined loop gets unrolled automatically.
```cpp
mul_lp: for (int k = 0; k < n; k++) {
#pragma HLS PIPELINE II=1
  y[k] = p[k] * q[k];
}
```

Source: UG1399 v2023.2, Ch.3 Loops Primer > Pipelining Loops, pp. 62-64.
