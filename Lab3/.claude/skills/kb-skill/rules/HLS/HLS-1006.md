- One producer feeding one consumer maps naturally onto a FIFO or PIPO channel, which replaces lock-based handshaking (semaphores, mutexes, monitors) that is slow and hard to debug.
- PIPO = double buffer: the consumer reads a finished (older) block while the producer fills the other one; they swap when the new block is valid, so synchronization is per block.
- FIFO: the consumer may read an element as soon as it is pushed, so downstream tasks run pipelined with their producer, and a join task can also overlap with its inputs.
- FIFO deadlock: production and consumption rates differ between tasks, and a wrongly sized FIFO can then deadlock the design, most typically when there are several producers and consumers. Fix: adjust FIFO depths, or use PIPOs if the earlier start is not needed.
- Granularity: a transfer carries a block of one value or N values; bigger blocks need more memory.

Source: UG1399 v2023.2, Ch.1 Design Principles > Streaming Data Paradigm, pp. 29-38.
