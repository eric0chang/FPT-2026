Mixed-format operands need no manual alignment: binary points are lined up before the operation. Operands may be ap_[u]fixed, ap_[u]int or C/C++ integers.
Worked with `ap_fixed<75,62>` (I 62, F 13) and `ap_fixed<5,2>` (I 2, F 3): sum or difference -> `ap_fixed<76,63>`, product -> `ap_fixed<80,64>`.
Division conflict: the text's rule gives the quotient I(a)+F(b) = 65 integer and 13 fraction bits, but the manual's own example stores it in `ap_fixed<84,66>`. For signed operands the extra integer bit is needed (most negative a divided by -1 LSB of b gives 2^(I(a)-1+F(b)), just past the rule's range), so keep it and confirm in C simulation.
```cpp
ap_fixed<8,4>  a = 3.375;  // I 4, F 4
ap_ufixed<6,5> b = 12.5;   // I 5, F 1
ap_fixed<6,3>  c = -2.25;  // I 3, F 3
ap_fixed<11,7> s = a + b;  // 15.875, exact
ap_fixed<14,7> m = a * c;  // I 4+3, F 4+3: -7.59375, exact
```
A narrower destination is legal; its Q/O modes (default truncate and wrap) then decide the value. To control resources, AMD recommends choosing the width of the stored result rather than widths of individual operations (their case: an hls_math power function such as rsqrt).

Source: UG1399 v2023.2, Ch.20 Arbitrary Precision Data Types Library > C++ Arbitrary Precision Fixed-Point Types: Reference Information > Binary Arithmetic Operators, pp. 699-709.
