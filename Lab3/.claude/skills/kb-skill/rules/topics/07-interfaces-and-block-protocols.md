# Topic 7: Interfaces and block protocols (32 rules)

Covers: axis, ap_fifo/ap_memory/ap_vld ports, ap_ctrl_*, Vivado IP flow. `must` / `must-not` first. Full rule: `../HLS/<ID>.md`.

| ID | Type | Summary | Tags |
|---|---|---|---|
| HLS-1080 | must | Global variables are synthesizable but never become top-level ports (config_interface -expose_global is unsupported and errors out); pass any data shared with the test bench, host or other kernels as an explicit top-level argument. A global used only inside the design stays internal storage. | global-variable, interface, migration, port, top-level |
| HLS-1103 | must | Use ap_fifo (Vivado IP stream protocol, default for hls::stream arguments) only for data accessed sequentially; AMD strongly recommends modeling that data as hls::stream<T>, which implements a FIFO. | ap_fifo, hls-stream, streaming, vivado-ip |
| HLS-1129 | must | For array arguments streamed via axis, ap_fifo or STREAM (struct arrays included), access each element strictly in order with exactly one whole-element read and one write through a local copy (read, modify the copy, write), never members directly on the argument; prefer hls::stream arguments. | ap_fifo, axis, hls-stream, sequential-access, struct |
| HLS-1131 | must | ap_none ports (default for scalars and input pointers; not allowed on array arguments) have no handshake: the producer must supply input data before start or hold it until ap_ready, and the consumer must read outputs after the block is done and before it restarts. | ap_none, ap_ready, array, port-protocol, timing |
| HLS-1134 | must | Use ap_fifo or ap_hs on an array/pointer argument only if it is accessed strictly in sequence, and ap_fifo only on a pure input or pure output. HLS errors if it proves otherwise, but if it cannot tell it only warns (XFORM-124) and builds the port anyway, and RTL/co-sim then mismatch. | ap_fifo, ap_hs, inout, sequential-access, xform-124 |
| HLS-1146 | must | Set the block protocol on the function return: data-driven TLP requires ap_ctrl_none; control-driven TLP uses ap_ctrl_chain or ap_ctrl_hs. When chaining HLS blocks prefer ap_ctrl_chain, since ap_ctrl_hs ties ap_continue to 1 and gives no back-pressure. | ap_ctrl_chain, ap_ctrl_hs, ap_ctrl_none, block-protocol, task-level-parallelism |
| HLS-1148 | must | When RTL drives an ap_ctrl_chain or ap_ctrl_hs block, hold ap_start High until ap_ready pulses; send new inputs on ap_ready and take results (and ap_return) on ap_done, which coincide only in non-pipelined designs. ap_continue Low at ap_done stalls the block. | ap-continue, ap-start, ap_done, ap_ready, handshake |
| HLS-1150 | must | Static/global variables get their C initial value only at bitstream load and RTL-sim start; to restore it on every reset, keep the default reset=control and add `#pragma HLS reset variable=<v>` to just those variables (state/all reset every such block-RAM array: many cycles, more area). | bram, config_rtl, initialization, reset, static |
| HLS-1212 | must | Cosim runs only if at least one holds: top uses ap_ctrl_chain or ap_ctrl_hs; the design is purely combinational; the top-level II is 1; or every interface array streams via axis or ap_hs; else it aborts with SIM-345. ap_ctrl_none on port=return removes all handshakes, so check this before using it. | ap_ctrl_none, block-protocol, cosim, interface |
| HLS-1247 | must | Use the INTERFACE pragma only on arguments and the return of the top-level function; it is not supported on sub-functions, whose port protocols Vitis HLS derives automatically (the only control there is whether a port is registered). | interface, port, sub-function, top-function |
| HLS-1248 | must | For pointer arguments of the top function, set INTERFACE depth= to the largest number of samples the test bench sends; RTL co-simulation needs it to size the verification adapter's FIFO. | cosim, depth, interface, pointer |
| HLS-1327 | must | To control AXI4-Stream side-channel signals from C/C++, use a struct whose member names match the AXI4-Stream side-channel signal names; these members are treated as data and are registered whenever TDATA is registered. | axis, interface, migration, side-channel |
| HLS-1083 | must-not | Do not use pointer arithmetic that accesses a top-level pointer out of order, or not starting from element 0, with wire, handshake or FIFO interfaces; make the argument an array and use an ap_memory (RAM) interface for indexed access. | ap_memory, fifo, interface, pointer-arithmetic, top-level |
| HLS-1123 | must-not | Do not use hls::axis, ap_axiu or ap_axis on internal functions or local variables; the AXI4-Stream protocol exists only on top-level function interfaces. Use hls::stream for streams inside the design. | ap_axiu, axis, hls-stream, top-level |
| HLS-1133 | must-not | Do not return a pointer from the top-level function; a top-level return value becomes the ap_return output port, whose data is valid when ap_done is asserted. | ap_done, ap_return, return, top-level |
| HLS-1135 | must-not | Do not use ap_ack on an output port if the design must be verified with C/RTL co-simulation; co-simulation cannot verify designs that use ap_ack on outputs. | ap_ack, cosim, port-protocol |
| HLS-1232 | must-not | Do not use BIND_STORAGE on top-level function arguments; set their memory type and implementation with the INTERFACE pragma's storage_type and storage_impl options, since that memory type decides how many and which RTL ports are created. | bind_storage, interface, storage_type, top-level |
| HLS-1250 | must-not | Do not use the INTERFACE register option on port=return, which is unsupported; to register the function return, use #pragma HLS LATENCY min=1 max=1 instead. | interface, latency, register, return |
| HLS-1124 | pitfall | axis data is padded to whole bytes (a 12-bit type becomes 16 bits, sign- or zero-extended by signedness) and a struct on an axis port is aligned to its widest member, so expect TDATA wider than the sum of member widths. | alignment, axis, padding, struct |
| HLS-1151 | pitfall | With AXI4 interfaces in the design, reset is forced active-Low (with a reset-level warning) whatever polarity the RTL configuration requests, including the default active-High, because AXI4 requires it; drive and verify the reset as active-Low (Vitis kernels show ap_rst_n). | active-low, axi, config_rtl, reset |
| HLS-1097 | recipe | Interface defaults depend on the flow: Vitis kernels use only AXI adapters (scalar/reference -> s_axilite, array/pointer-to-array -> m_axi, hls::stream -> axis, ap_ctrl_chain); Vivado IP uses ap_none/ap_vld/ap_ovld, ap_memory, ap_fifo, ap_ctrl_hs. Use INTERFACE to override (e.g. AXI in Vivado IP). | interface, m_axi, s_axilite, vitis-kernel, vivado-ip |
| HLS-1100 | recipe | For an axis port, declare it as hls::stream of an ap_axis struct (with or without side-channels) and carry your payload type in TDATA; do not write your own struct to model TLAST, TVALID or side-channel signals. | ap-axis, axis, hls-stream, side-channel |
| HLS-1128 | recipe | To process AXI4-Stream packets with side-channels, loop over ap_axiu/ap_axis beats: copy each input beat's last flag to the output beat, set keep explicitly (e.g. all ones), and stop after the beat with last set; pipeline the loop at II=1. | axis, pipeline, side-channel, tkeep, tlast |
| HLS-1136 | recipe | For ap_memory array arguments, set the RAM type with BIND_STORAGE before synthesis: a single-port RAM forces a single-port interface, while unconstrained HLS uses dual-port only if it lowers II; a slower RAM's read latency is also declared there. | ap_memory, array, bind_storage, latency |
| HLS-1200 | recipe | Set flow_target deliberately (default Vivado IP flow; `vitis` for kernels; in Tcl open_solution -flow_target vivado\|vitis, which replaces deprecated config_sdx): with argument types, default interface mode and INTERFACE pragmas it decides the generated top-level interfaces. | flow-target, interface, vitis, vivado-ip |
| HLS-1049 | direction | Partitioning a top-level array argument gives each sub-array its own interface; complete partitioning turns every element into a separate scalar port, giving maximum parallel access but many more ports and possible routing trouble in implementation. | array-partition, interface, port, routing |
| HLS-1101 | direction | For data that enters or leaves sequentially from a streaming source (another kernel, a video processor), prefer axis over m_axi: no address logic, bursts of unlimited length, fewer resources. Keep m_axi for addressed global memory (DDR/HBM/PLRAM) shared with the host or other kernels. | axis, m_axi, resource, streaming |
| HLS-1126 | direction | Choose the axis signal set by element type: plain hls::stream<T> gives TDATA/TVALID/TREADY only (fewest resources, no end-of-stream); hls::axis/ap_axiu/ap_axis add TKEEP/TSTRB/TLAST and, for non-zero widths, TUSER/TID/TDEST; trim with EnableSignals or hls::axis_data/axis_user. | ap_axiu, axis, side-channel, tkeep, tlast |
| HLS-1127 | direction | When connecting HLS IPs through AXI4-Stream, make at least one side of each link a registered interface (default mode is 'both') or put an AXI4-Stream Register Slice between them, so no combinational feedback path forms. | axis, register, register-slice, timing |
| HLS-1132 | direction | Put a handshake on outputs (output pointers default to ap_vld) rather than ap_none so consumers know when data is valid; choose full ap_hs where neither side should depend on timing assumptions, at the cost of extra valid/ack ports. | ap_ack, ap_hs, ap_ovld, ap_vld, port-protocol |
| HLS-1137 | direction | Pick ap_memory (word addressing, ceil(log2(depth))-bit address, any word width, discrete ports) or bram (byte addressing, 32-bit address, 8*2^k-bit words, one grouped port usable with Block/Embedded Memory Generator in IP integrator) to match the memory you connect. | ap_memory, array, bram, ip-integrator |
| HLS-1159 | direction | Choose top-level argument types knowing their RTL mapping: each scalar becomes a data port as wide as its C type (char -> 8 bit, int return -> 32 bit), and an array argument becomes ports to an external RAM (address, data, chip/write enable). | array, bit-width, interface, port |
