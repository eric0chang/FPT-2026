# Topic 12: Functions and hierarchy (16 rules)

Covers: INLINE, top function, templates, classes, recursion, static. `must` / `must-not` first. Full rule: `../HLS/<ID>.md`.

| ID | Type | Summary | Tags |
|---|---|---|---|
| HLS-1065 | must | The synthesis top must be exactly one plain, non-static, non-template function (not a class, a class member function or a template), set with syn.top; to synthesize several functions or a class, call them from that single top-level wrapper and instantiate the class inside it. | class, static, syn-top, template, top-level |
| HLS-1224 | must | Write ALLOCATION with its type (function or operation) directly after the allocation keyword; type function only covers functions not inlined (by INLINE or automatically by HLS); for a template function use instances=foo<DT>, as plain instances=foo is invalid. | allocation, inline, template |
| HLS-1238 | must | DATAFLOW is not hierarchical: tasks nested inside a sub-function or loop of a dataflow region are only overlapped if you also add DATAFLOW to that sub-function or loop, or inline the sub-function into the dataflow region. | dataflow, hierarchy, inline |
| HLS-1262 | must | Class members are reset only via the RESET pragma (config settings skip them): target public members, never from a constructor; inside a method only static members work; on an object in the top/sub-function a non-static member works only if the object is static. | class, reset, static |
| HLS-1265 | must | #pragma HLS top name=<n> only labels a function (typically a class member function); you must still run set_top <n> (or select it as top in the project settings) for it to become the synthesized top. | class, set-top, top |
| HLS-1067 | must-not | Do not use a global variable or a class data member as the loop index in a C++ class method: it blocks unrolling (XFORM-503: cannot unroll ... variable loop bound) and with it pipelining of any loop or function that uses the class. Declare loop counters as local variables of the method. | class, loop-index, pipeline, unroll, xform-503 |
| HLS-1094 | must-not | Do not write recursive functions for synthesis: neither multiple nor tail recursion (even with finitely many calls) is supported, though ordinary calls are fine; implement a tail-recursive algorithm with C++ template recursion on a template parameter, ended by an explicit specialization (e.g. N=1). | function, recursion, template, unsupported |
| HLS-1336 | must-not | Do not give a top-level function argument an enum type (including enums used in structs, arrays or pointers), _Complex, _Half or __fp16 in Vitis HLS; these argument types are unsupported and draw a warning or an error. | data-type, enum, top-function, unsupported |
| HLS-1223 | pitfall | An ALLOCATION operation limit only covers the function it is placed in, not that function's sub-functions; to cap e.g. multipliers inside callees, add ALLOCATION in each sub-function or inline them into the limited function. | allocation, hierarchy, inline, mul |
| HLS-1244 | pitfall | Vitis HLS inlines some functions itself (small ones, and those called in a loop pipelined at II=1, also when PERFORMANCE infers II=1); an inlined function's pragmas are ignored and it vanishes from RTL files, reports and Function Call Graph. Put INLINE off in a function that must keep its module. | hierarchy, inline, pragma-ignored, report |
| HLS-1246 | pitfall | INLINE recursive in a DATAFLOW region is ignored when inlining everything would collapse the region into a single function that no longer meets the dataflow conditions. | dataflow, inline, pragma-ignored |
| HLS-1057 | recipe | When a function is called with different constant values for one argument, apply FUNCTION_INSTANTIATE variable=<arg> (plus INLINE off so a small function is not auto-inlined) to get one constant-specialized RTL block per call with simpler control logic instead of one shared generic block. | area, function-instantiate, hierarchy, inline |
| HLS-1068 | recipe | Each distinct set of template argument values yields a separate function copy that HLS synthesizes and optimizes in its own context; a static inside a template function is likewise duplicated per argument set, so each instance keeps its own state. | cpp, instance, static, template |
| HLS-1195 | recipe | To synthesize just one sub-function, point syn.top at it: its callers and any peer functions the test needs then act as test bench code, even in the same file as the new top, so that file must also be registered as a test bench file. | syn-top, testbench, top-function |
| HLS-1245 | recipe | To flatten a whole call tree except chosen functions, put INLINE recursive in the parent's body and INLINE off inside each function to keep; plain INLINE only inlines the function it sits in, one level up into its callers. | hierarchy, inline, recursion |
| HLS-1055 | direction | INLINE dissolves a function into its caller so its logic is optimized and shared with the caller's (small functions inline automatically; INLINE off keeps a module, recursive flattens all below); a multiply-called function then loses its shared instance, which can grow area. Avoid huge functions. | area, hierarchy, inline, resource-sharing |
