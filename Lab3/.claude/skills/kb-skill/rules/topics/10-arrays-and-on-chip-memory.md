# Topic 10: Arrays and on-chip memory (13 rules)

Covers: ARRAY_PARTITION/RESHAPE, BRAM/URAM/LUTRAM, BIND_STORAGE, memory ports, ROMs, initialization. `must` / `must-not` first. Full rule: `../HLS/<ID>.md`.

| ID | Type | Summary | Tags |
|---|---|---|---|
| HLS-1227 | must | ARRAY_PARTITION/ARRAY_RESHAPE: type=block (consecutive chunks) or cyclic (round-robin) needs factor=; complete (default, one element each) takes none; dim=k splits only dimension k (1 = first), dim=0 all. On ARRAY_PARTITION, off=true cannot be combined with dim=, factor= or type=. | array-partition, array-reshape, default, dim, factor |
| HLS-1233 | must | BIND_STORAGE accepts only the listed combos: RAM/ROM latency 1-3, FIFO 1-4; ECC impls only with RAM_S2P; RAM_T2P only BRAM/URAM; ROM_NP only BRAM/LUTRAM; SRL and MEMORY only for FIFOs. Global config_storage covers FIFOs only. | bind_storage, bram, fifo, latency, uram |
| HLS-1046 | pitfall | When a pipelined or unrolled loop needs more accesses per cycle to one array than its RAM has ports (1 single-port, 2 dual-port), HLS reports SCHED-69 'Unable to schedule load ... due to limited memory ports' and a Final II above the target; partition, reshape or restructure to supply them. | array-partition, bandwidth, ii, memory-ports, sched-69 |
| HLS-1270 | pitfall | After moving to 2023.2, a design may start failing dataflow checks because `= {0}` or `= {}` on an AP-typed array now zero-fills every element and that fill is inferred as an extra write access; remove such initializers where the zeros are not needed. | 2023.2, array, dataflow, initialization |
| HLS-1047 | recipe | For a sliding-window computation over a RAM-mapped array, preload the first elements into scalars and rotate them each iteration so the loop reads the array once per iteration; II=1 then works with a single-port RAM. Try array pragmas first. | array, ii, memory-ports, pipeline |
| HLS-1052 | recipe | Declare read-only arrays const to get a ROM (initialized in RTL and bitstream, no reset needed; small ones may be auto-partitioned instead), as inference is not guaranteed; a code-filled local static array is inferred as a ROM when fully written before any read and never written again. | array, const, inference, rom, static |
| HLS-1053 | recipe | If a lookup table is filled with complex expressions (e.g. math.h sin()), move the fill loop into its own function and call it from the user; a ROM can then be inferred and, since the results are constants, no sin core is built in the RTL. | initialization, lookup-table, math, rom |
| HLS-1160 | recipe | To infer a shift register, keep a local array and inside the outer loop move every element down one slot (A[i] = A[i+1]), then write the newest value into the last slot; it shifts once per cycle and allows one random read anywhere per cycle, more flexible than a FIFO. | array, inference, shift-register |
| HLS-1234 | recipe | Use BIND_STORAGE latency= to add pipeline stages to an internal memory when RTL synthesis has timing trouble, or on interface block RAMs to model a non-standard off-chip SRAM with latency 2 or 3; default -1 lets HLS choose. | bind_storage, latency, sram, timing |
| HLS-1045 | direction | Expect internal arrays to become RAM, ROM or shift registers: per the manual, under 1024 elements gives a shift register, larger gives BRAM/LUTRAM/URAM (steer with BIND_STORAGE); full partition into registers is fully parallel only if registers suffice. | array, bind_storage, memory, shift-register |
| HLS-1050 | direction | Declare arrays meant as memories, especially initialized tables, `static`: a non-static initialized local array is rewritten into its RAM on every call (N cycles on a single-port RAM, stalling dependent work), while static contents are preset in RTL and bitstream. | array, initialization, ram, static |
| HLS-1155 | direction | Use distributed RAM for small fast buffers or small ROMs because its asynchronous read gives the value in the same cycle; for memories larger than about 128 bits, block RAM or UltraRAM gives better performance and lower power. | bram, distributed-ram, storage, uram |
| HLS-1226 | direction | For parallel array access, ARRAY_PARTITION splits an array into several RAMs or into registers (more ports, paid in memory instances or registers), whereas ARRAY_RESHAPE keeps one array with fewer, wider words and uses fewer block RAMs; pick reshape when BRAM count matters. | array-partition, array-reshape, bram, memory-ports |
