# Topic 14: Unsupported constructs and coding rules (11 rules)

Covers: dynamic memory, pointers, volatile, system calls, __SYNTHESIS__, undefined behaviour. `must` / `must-not` first. Full rule: `../HLS/<ID>.md`.

| ID | Type | Summary | Tags |
|---|---|---|---|
| HLS-1087 | must | A top-level pointer read or written more than once per call must be volatile (else only its first read and last write remain) and needs INTERFACE depth set to its accesses per call (e.g. depth=4 for four reads); otherwise co-simulation assumes one value and the RTL stalls. | cosim, depth, interface, pointer, volatile |
| HLS-1081 | must-not | Never use a pointer-to-pointer as an argument of the top-level function, and never let the elements of a pointer array point to other pointers; each pointer-array element may target only a scalar or an array of scalars. | pointer, pointer-array, pointer-to-pointer, top-level, unsupported |
| HLS-1082 | must-not | Cast pointers only between native C/C++ types (e.g. int* to char*); general pointer casts, such as writing a struct through its address reinterpreted as unsigned*, are not supported for synthesis, so assign each field instead. | pointer, pointer-cast, struct |
| HLS-1089 | must-not | Do not leave operating-system calls (file I/O, getc, time, sleep, ...) in code to be synthesized; remove them or guard them with #ifndef __SYNTHESIS__. Display-only calls such as printf and fprintf(stdout,...) are ignored by synthesis. | file-io, printf, synthesis-macro, system-call |
| HLS-1090 | must-not | Never #define or #undef __SYNTHESIS__ yourself, in source or through compiler options, and do not use it in the test bench; the tool defines it only for synthesis, and C simulation and co-simulation do not honour it. | csim, macro, synthesis-macro, testbench |
| HLS-1091 | must-not | Use __SYNTHESIS__ only to drop non-synthesizable side code such as debug file writes, never to change what the design computes; otherwise C simulation and the synthesized RTL can disagree, and such bugs are hard to debug. | csim, synthesis-macro, verification |
| HLS-1092 | must-not | Do not use malloc, alloc, free, or C++ objects created or destroyed dynamically in code to be synthesized; give every array a compile-time size, including function array parameters (`d[16]`, not `d[]`), and use fixed-size, bounded storage declared in the design. | array-size, bounded, dynamic-memory, malloc, unsupported |
| HLS-1095 | must-not | Do not use function pointers or virtual functions in code to be synthesized; Vitis HLS supports neither and reports a warning or an error. | function-pointer, pointer-cast, unsupported, virtual-function |
| HLS-1096 | must-not | Do not use C++ STL code in synthesized functions: Vitis HLS cannot synthesize the STLs, which use recursion and dynamic allocation; write a local equivalent without recursion or dynamic memory/objects. std::complex is allowed, but not std::complex<long double>. | dynamic-memory, recursion, std-complex, stl, unsupported |
| HLS-1066 | recipe | Debug prints with cout or printf may stay in synthesizable code: Vitis HLS discards these unsynthesizable system calls during synthesis (INFO SYNCHK-101), so they only affect C simulation. | cout, printf, simulation, synchk-101 |
| HLS-1093 | recipe | To remove malloc without rewriting pointer code, declare a fixed-size local array and point the existing pointer at it; switch between versions with your own macro (not __SYNTHESIS__) and check both give identical C-simulation results before synthesizing. | csim, dynamic-memory, malloc, pointer |
