# Topic 13: Resources, binding and sharing (11 rules)

Covers: BIND_OP, ALLOCATION, DSP mapping, operator sharing, expression balancing. `must` / `must-not` first. Full rule: `../HLS/<ID>.md`.

| ID | Type | Summary | Tags |
|---|---|---|---|
| HLS-1181 | must | BIND_OP selects operators through a variable, so to control only one of several identical operators in one expression (e.g. x*y*z) you must split it, assigning that operator's result to its own temporary, and apply BIND_OP to the temporary. | bind_op, coding-style, multiplier |
| HLS-1231 | must | BIND_OP latency= needs a multi-stage implementation and must lie in the supported range for the op/impl pair (e.g. add/mul on fabric or dsp: 0-4; sub on dsp: 0 only; fmul maxdsp: 0-7); default -1 lets HLS choose. primitivedsp is Versal-only; comparisons (dcmp) cannot be bound. | bind_op, dsp, floating-point, latency |
| HLS-1183 | pitfall | A non-inlined MULADD/MAC function with a fixed latency (e.g. 2) cannot be matched to a DSP accumulator running at II=1; inline the MAC function so the accumulation can be matched. | accumulator, dsp, ii, inline, muladd |
| HLS-1229 | pitfall | Avoid BIND_OP impl=dsp on operators you expect HLS to fuse into DSP multi-op patterns (MULADD, AMA, ADDMUL and subtract forms): BIND_OP takes no part in that matching and can block it. If a pipelined MAC loop's mul-add isn't matched, drop that BIND_OP and add EXPRESSION_BALANCE off. | bind_op, dsp, expression-balance, muladd, pipeline |
| HLS-1056 | recipe | To share one function instance between calls at different hierarchy levels, inline the intermediate wrapper so all calls sit in one function, then apply ALLOCATION function instances=<f> limit=1 there; only calls at the same level can share. | allocation, area, inline, sharing |
| HLS-1180 | recipe | To cut area, cap instances with ALLOCATION in a function, loop or region body (operation, e.g. instances=mul limit=N; or function, e.g. limit=1 so all calls share one block) so HLS must share units across cycles, at a possible latency/throughput cost; type= can cap implementations instead. | allocation, area, binding, dsp, resource-sharing |
| HLS-1182 | recipe | For DSP multi-operation matching (add/sub->mul, mul->add/sub, add->mul->add), keep each fragment fanout-free with operand and intermediate widths within the DSP ports; a product reused by two expressions is pulled out by CSE and fans out, so isolate each in a non-inlined function. | bit-width, cse, dsp, inline, muladd |
| HLS-1209 | recipe | Use the Bind Op and Bind Storage reports to see how operations and arrays were mapped (implementation, latency, pragma vs auto); raise an op's latency with BIND_OP to break a long combinational path when fixing timing, and use BIND_STORAGE to retarget memories to available resources. | bind_op, bind_storage, bram, dsp, timing |
| HLS-1230 | recipe | To force one operation's implementation, put BIND_OP in the function defining its result variable: variable= names the variable assigned the op's result, impl= picks fabric or dsp (op=mul impl=fabric keeps it off DSPs), latency=N its pipeline depth. Ops you do not bind stay tool-chosen. | bind_op, dsp, fabric, latency, timing |
| HLS-1243 | direction | Expression balancing (operator chains rebuilt as trees) is on by default for integers (4 chained adds: 4 to 2 cycles) but off for float/double, kept in C order to match C sim unless unsafe_math_optimizations is set; set per scope with expression_balance [off]: lower latency vs area, no sharing. | area, expression-balance, floating-point, latency, unsafe-math |
| HLS-1252 | direction | Treat LATENCY as a soft constraint: an unmeetable max only yields a warning and the lowest latency found, a min above the achievable value adds dummy cycles that may enable more sharing; both narrow the search, so equal min and max on loops, functions or regions can cut synthesis runtime. | constraint, latency, resource-sharing, runtime |
