# LeNet HLS IP to Hardware

**Category:** Design Capture + High-Level Synthesis
Model-to-bitstream flow — the HLS Knowledge Base guides the AI from a Keras model to an IP, and the Lab2 platform carries it to the board.

## Overview

Lab2 built a **DMA loopback via DDR** on the AMD AUP-ZU3 with a passthrough `axis_filter` in the AXI-Stream path. Lab3 keeps that platform and replaces `axis_filter` with a **LeNet inference IP generated by Vitis HLS**.

The model (`model/custom_lenet_model.h5`) is a mini LeNet whose first activation is a custom **HardSwish** layer. The AI writes the HLS C++ from scratch, guided by the **HLS Knowledge Base** (`/kb-skill`): past designs from the KB database (Track 1) and 230 design rules from AMD UG1399 (Track 2).

One prompt takes you from `.h5` to bitstream, a second one (optional) to the board notebook:

1. **HLS IP + Vivado** (Step 2) — `.h5` → C++ → csim → csynth → cosim → IP → swapped into the Lab2 block design → bitstream
2. **PYNQ** (Step 5) — run 1000 MNIST images on the board and compare with Keras

## Step-by-Step Instructions

### Step 1 — Open the example

```bash
cd Lab3
claude
```

Type `/mcp` and check that the Vivado MCP server is connected.

### Step 2 — Build the HLS IP and the bitstream

Paste this prompt into Claude:

```
/kb-skill
Convert the Keras model model/custom_lenet_model.h5 (custom layer in
model/custom_layers.py) into a Vitis HLS IP according to spec/hls_spec.md.
Write the HLS C++ from scratch, using the HLS Knowledge Base.
Then swap the IP into the Lab2 block design according to spec/hardware_spec.md,
build through bitstream and report timing.
```

`/kb-skill` loads the Knowledge Base. The agent then reads the specs and autonomously:

1. Looks up the Knowledge Base: similar past designs (Track 1) and the rules that apply (Track 2)
2. Extracts the weights from the `.h5` and 20 test vectors from `data/mnist_test_1000.npz` into `.inc` files
3. Writes `lenet.h`, `lenet.cpp`, `lenet_tb.cpp`, citing the rules it applies
4. Runs csim (20 images vs. Keras), csynth (once), cosim (2 images), and exports the IP to `hls/lenet_prj/solution1/impl/ip/`
5. Opens the Lab2 project through Vivado MCP, saves a copy as `vivado/aup_zu3_lenet.xpr`, replaces `axis_filter` with `lenet_axis_0`
6. Runs synthesis, implementation and bitstream, writes the reports, copies `lenet.bit` / `lenet.hwh` to `pynq/`

**Interface contract** (fixed by the spec, so the IP drops into the Lab2 slot):

| Item | Value |
|------|-------|
| Top | `lenet_axis(s_axis, m_axis)`, `ap_ctrl_none` |
| Input | 784 × float32 per image (`pixel / 255.0`, row-major) |
| Output | 10 × float32 softmax probabilities, `TLAST` on the 10th word |

The block design is the Lab2 design with one block swapped: DMA `M_AXIS_MM2S` → **`lenet_axis_0`** → DMA `S_AXIS_S2MM`. Address map and PS settings are unchanged; `lenet_axis` has no AXI-Lite port and no address.

### Step 3 — Review results

| Metric | HLS (csynth / cosim) | Vivado (post-route) |
|--------|----------------------|---------------------|
| Latency per image | _from `hls/REPORT.md`_ | — |
| LUT / FF / DSP / BRAM | _from `hls/REPORT.md`_ | _`lenet_axis_0` row of `vivado/utilization_hier.rpt`_ |
| WNS / WHS | — | _from `vivado/timing_summary.rpt`_ |

`hls/REPORT.md` also lists which past design and which rules (`HLS-####`) the agent used. To see the block design, open `vivado/aup_zu3_lenet.xpr` in the Vivado GUI.

### Step 4 — Load bitstream on AUP-ZU3 through PYNQ Jupyter Notebook

The build places `lenet.bit` and `lenet.hwh` in `pynq/` (`spec/hardware_spec.md` §8). Also copy the test set next to the notebook:

```bash
cp data/mnist_test_1000.npz pynq/
```

Copy the `.bit`, `.hwh`, `.npz` and `.ipynb` to the board:
- Open browser and connect board through http://192.168.3.1:9090
- Password: xilinx
- Create new folder
- Upload the four files to the new folder

### Step 5 — Verify inference on hardware

Run `pynq/lenet_inference.ipynb`, or ask the agent to generate one:

```
Provide a PYNQ jupyter notebook that runs LeNet inference on the AUP-ZU3
with pynq/lenet.bit, using the images in data/mnist_test_1000.npz, and
compares the board output with keras_probs.
And write markdown description in notebook.
```

The notebook sends each image through CPU → DDR → DMA MM2S → `lenet_axis` → DMA S2MM → DDR → CPU and passes when:

- top-1 agreement with Keras ≥ 99 %
- board accuracy ≥ Keras accuracy (96.70 %) − 0.5 %

## What You'll Learn

- How a **model spec plus an interface contract** lets the AI write an HLS accelerator from scratch, including a custom layer
- How the **HLS Knowledge Base** feeds the AI past designs and design rules before it writes code, and why the flow must go past csynth (cosim, IP export) before the IP is ready for Vivado
- How a fixed AXI-Stream contract makes the HLS IP a **drop-in replacement** in an existing, already-verified block design
